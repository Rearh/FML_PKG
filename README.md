# fml_pkg

Минималистичный source-based пакетный менеджер для Linux From Scratch (LFS), написанный на чистом Python без внешних зависимостей.

## Принцип работы

`fml_pkg` работает по принципу изолированной сборки из исходного кода с отслеживанием файлов через манифесты:

1. **Синхронизация (`sync`)**
   Пакетник скачивает индексный файл `repo.json` из корня репозитория и сохраняет его локально в `/var/lib/fml_pkg/repo.json`.
2. **Изолированная сборка (`install`)**
   - Создаётся временная песочница в `/tmp/fml_pkg-<имя>-XXXXXX/` с двумя директориями: `build/` (для распаковки и компиляции) и `pkg/` (виртуальный корень системы, передаваемый в переменную окружения `$DESTDIR`).
   - Скачивается скрипт сборки `build.sh` и запускается от `bash` внутри `build/`.
   - Рецепт устанавливает скомпилированные бинарники и библиотеки не напрямую в `/`, а в `$DESTDIR`.
3. **Учёт файлов и установка в систему**
   - `fml_pkg` рекурсивно обходит `$DESTDIR`, переносит все файлы и символические ссылки в реальный корень `/` и записывает их точные пути в манифест `/var/lib/fml_pkg/manifests/<имя>.list`.
   - Версия пакета фиксируется в `/var/lib/fml_pkg/installed.json`.
   - Временная папка в `/tmp` автоматически удаляется.
4. **Обновление (`update`) и удаление (`remove`)**
   - При обновлении `fml_pkg` сравнивает версию в `installed.json` с `repo.json`. Если версия изменилась — запускает пересборку и удаляет «осиротевшие» файлы, которых больше нет в новой версии.
   - При удалении читается `<имя>.list`, удаляются все файлы пакета и зачищаются опустевшие директории.

## Структура репозитория

```text
FML_PKG/
├── bin/
│   └── fml_pkg                 # Исполняемый код пакетного менеджера
├── config/
│   └── fml_pkg.conf            # Конфигурация (URL репозитория)
├── recipes/                    # База рецептов по категориям
│   ├── core/                   # Базовые системные утилиты
│   ├── libs/                   # Библиотеки
│   └── extra/                  # Пользовательский софт
│       └── fastfetch/
│           └── build.sh        # Рецепт сборки пакета
├── scripts/
│   ├── install_self.sh         # Скрипт установки пакетника в LFS
│   └── gen_index.py            # Генератор индекса repo.json
└── repo.json                   # Главный индекс пакетов (генерируется автоматически)
```

## Установка и команды

Первичная установка пакетного менеджера в LFS:
```bash
sudo ./scripts/install_self.sh
```

Основные команды (требуют прав `root`):
* `sudo fml_pkg sync` — скачать свежий индекс пакетов из репозитория.
* `sudo fml_pkg install <пакет>` — скачать рецепт, собрать и установить пакет.
* `sudo fml_pkg update [пакет]` — обновить все установленные пакеты (или один указанный).
* `sudo fml_pkg remove <пакет>` — полностью удалить пакет из системы.

## Гайд для разработчиков: добавление пакета

### Шаг 1. Создайте директорию рецепта
Выберите подходящую категорию (`core`, `libs` или `extra`) и создайте папку с именем пакета:
```bash
mkdir -p recipes/extra/<имя_пакета>
```

### Шаг 2. Напишите скрипт сборки `build.sh`
Создайте файл `recipes/extra/<имя_пакета>/build.sh`.

**Обязательные правила для рецептов:**
1. В первых 15 строках укажите метаданные в комментариях `# name:` и `# version:` — их считывает генератор индекса `gen_index.py`.
2. Всегда добавляйте `set -e`, чтобы сборка мгновенно прерывалась при любой ошибке компиляции.
3. Используйте `--prefix=/usr` при конфигурации.
4. Финальная установка **обязательно** должна идти в `"$DESTDIR"`, иначе пакетник не сможет отследить файлы для последующего удаления.

**Шаблон `build.sh` для Autotools (`./configure`):**
```bash
#!/bin/bash
# name: htop
# version: 3.3.0

set -e
wget https://github.com
tar -xf htop-3.3.0.tar.xz
cd htop-3.3.0

./configure --prefix=/usr
make -j\$(nproc)
make DESTDIR="\$DESTDIR" install
```

**Шаблон `build.sh` для CMake:**
```bash
#!/bin/bash
# name: fastfetch
# version: 2.31.0

set -e
wget https://github.com
tar -xf 2.31.0.tar.gz
cd fastfetch-2.31.0

cmake -B build -DCMAKE_INSTALL_PREFIX=/usr -DCMAKE_BUILD_TYPE=Release
cmake --build build -j\$(nproc)
DESTDIR="\$DESTDIR" cmake --install build
```

**Шаблон `build.sh` для Meson / Ninja:**
```bash
#!/bin/bash
# name: example
# version: 1.0.0

set -e
wget https://example.org
tar -xf example-1.0.0.tar.xz
cd example-1.0.0

meson setup build --prefix=/usr --buildtype=release
ninja -C build
DESTDIR="\$DESTDIR" ninja -C build install
```

### Шаг 3. Сгенерируйте индекс и запушьте изменения
После создания рецепта выдайте ему права на исполнение и обновите `repo.json`:
```bash
chmod +x recipes/extra/<имя_пакета>/build.sh
python3 scripts/gen_index.py
git add .
git commit -m "add <имя_пакета> recipe"
git push
```
